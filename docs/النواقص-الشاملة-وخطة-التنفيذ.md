# قائمة النواقص الشاملة + خطة التنفيذ — منصّة الأنظمة الموحّدة

> جُمعت من: «دليل النظام وخطة التطوير» + «هيكلة النظام» (PDF) + فحص كامل للكود وقاعدة البيانات — 2 يوليو 2026.
> الهدف: نظام ERP متكامل قابل للبيع والنسخ والتخصيص (نموذج Odoo).

## أ) نواقص جوهرية تنطبق على كل العملاء (أولوية عالية)

| # | النقص | الحالة الحالية | ملاحظات |
|---|-------|----------------|---------|
| 1 | **الصلاحيات والأدوار (أهم نقص)** — أدوار (مالك/مدير/موظف/مشاهد) + صلاحيات لكل تطبيق ولكل إجراء | جزئي: `memberships.role` + `allowed_apps` موجودة في DB لكن بلا تحكّم دقيق بالإجراءات ولا واجهة كاملة | أساس البيع لأي شركة فيها أكثر من موظف |
| 2 | إدارة المستخدمين داخل مساحة العميل (دعوة/تعيين دور/تعطيل) | جزئي: RPC `invite_member` و`tenant_members` موجودة؛ الواجهة ناقصة | تُبنى فوق (1) |
| 3 | سجل النشاط Audit / Chatter (نمط Odoo) — من غيّر ماذا ومتى + ملاحظات على كل سجل | غير موجود | يتطلب جدول `audit_log` + hooks في دوال الحفظ |
| 4 | الإشعارات والأنشطة — تذكيرات، متابعات، إشعارات داخل النظام / بريد / واتساب | غير موجود إطلاقاً | أكبر ثغرة في تجربة غرف العملاء: العميل يطلب تعديلاً ولا أحد يعرف |
| 5 | البحث الشامل عبر كل التطبيقات | غير موجود | Cmd+K عالمي |
| 6 | الاستيراد/التصدير (CSV/Excel) | تصدير JSON يدوي فقط | أساسي لإدخال بيانات العميل بسرعة عند البيع |
| 7 | المرفقات والمستندات لكل سجل | جزئي: bucket صور للتسليمات فقط | عقود، عروض، ملفات على أي سجل |
| 8 | التقارير والطباعة الموحّدة + **الفاتورة الإلكترونية ZATCA** | فواتير PDF + QR بسيط | ZATCA (المرحلة الثانية: التكامل) مهم جداً للبيع في السعودية |
| 9 | النسخ الاحتياطي التلقائي وتصدير بيانات العميل | يدوي فقط؛ كل البيانات في JSON واحد (`app_state`) | خطر فقدان بيانات حقيقي — snapshot دوري ضروري قبل أول عميل خارجي |
| 10 | معالج إعداد أوّلي (Onboarding wizard) + بيانات تجريبية عند إنشاء عميل جديد | جزئي: `demo_seed` موجودة وتُزرع تلقائياً للتجارب | يحتاج معالجاً موجّهاً (الهوية → الضريبة → المنتجات → الفريق) |
| 11 | بوابة دفع سعودية (Moyasar / Tap / Telr) للاشتراكات وفواتير العملاء | غير موجود — تعليم «مدفوعة» يدوي | شرط لمرحلة الاشتراكات (٥) |
| 12 | الأداء: pagination + lazy loading | كل البيانات تُحمَّل دفعة واحدة | سيتباطأ مع أول عميل نشيط |
| 13 | اختبارات آلية (Playwright على مسارات البيع الأساسية) | لا شيء | ملف واحد ضخم = أي تعديل قد يكسر شيئاً بصمت |
| 14 | مراجعة أمنية لدوال التوكن (`room_get`, `fl_room`…) وعزل الـ tenants | RLS مطبّقة؛ تحتاج اختبار اختراق بسيط | حرج قبل أول عميل خارجي |
| 15 | التجاوب الكامل مع الجوال (كل التطبيقات + غرف العملاء) | جيد جزئياً | «تصميم متناسب مع جميع المقاسات» = شرط البيع |

## ب) نواقص كل تطبيق (موجود / ينقصه)

| التطبيق | موجود | ينقصه |
|---------|-------|--------|
| الرئيسية | مؤشرات (محصّل، مستحقات، مشاريع، مهام) + مؤقّت تركيز | ويدجتس قابلة للتخصيص، فلترة بالفترة، رسوم بيانية |
| المكتب (Launchpad) | شبكة تطبيقات + خلفيات | ترتيب/تثبيت المفضّلة، بحث عن تطبيق |
| عنتر (المساعد) | مساعد سريع يضيف مهاماً | ربط فعلي ينشئ سجلات/مهاماً بالأوامر في كل التطبيقات |
| لوحات البيانات | نظرة عامة | KPIs قابلة للتخصيص، رسوم بيانية، فلترة زمنية، تصدير |
| المبيعات | تسجيل مبيعات وخصومات وربط بالفواتير | مسار: عرض سعر ← طلب ← فاتورة، تسجيل دفعات، تقارير بالفترة/المنتج |
| الفوترة | إنشاء فواتير + طباعة + ضريبة | حالات الدفع والدفعات الجزئية، فواتير دورية، الفاتورة الإلكترونية (ZATCA)، تذكير تحصيل |
| المنتجات | كتالوج وأسعار | تصنيفات، متغيّرات، مخزون/كميات، قوائم أسعار |
| الاشتراكات/المصروفات | تسجيل اشتراكات ومصروفات | تجديد/تنبيه انتهاء، اعتماد مصروفات، تصنيفات وتقارير |
| المهام (CRM) | مهام بمراحل (Kanban) | مصادر العملاء المحتملين، متابعات/أنشطة، تحويل لعميل، إسناد وصلاحيات |
| العملاء | دفتر عملاء | تمييز شركة/فرد، وسوم، منع التكرار، سجل تفاعلات، مرفقات |
| المواعيد | حجز وإدارة المواعيد | تذكيرات، تكرار، حجز موارد، ربط بالتقويم/العميل |
| التقويم | تقويم موحّد | مزامنة Google، تذكيرات، مشاركة |
| المشروع/الإنتاج | غرفة عميل وفريلانسر بالتوكن، تسليمات وتعديلات وتعليقات | مهام/مراحل داخل المشروع، سجلّات وقت (Timesheets)، ميزانية/ربحية |
| الفريق | إدارة الفريق بروابط خاصة | أدوار وصلاحيات، حضور/وقت، ربط بنظام المستخدمين |
| الإعدادات | هوية/ضريبة/خلفيات | إدارة المستخدمين والأدوار، نسخ احتياطي، تكاملات (واتساب/بريد)، تخصيص الترقيم |

## ج) لوحة التحكم المركزية (Super-Admin) — النواقص

**موجود:** عرض العملاء، تفعيل/إيقاف التطبيقات لكل عميل، إضافة عميل جديد.

**ينقصها:**
- إدارة مستخدمي وأدوار كل عميل (دعوة/تعطيل/تعيين دور).
- تعديل هوية العميل (شعار، ألوان، اسم، دومين) — White-label.
- الخطط والاشتراك والفوترة لكل عميل.
- إحصاءات الاستخدام، وإصدارات التطبيقات وسجل التغييرات.
- إنشاء عميل ببيانات تجريبية بضغطة واحدة.
- «تسجيل الدخول كعميل» للدعم، وتعطيل/أرشفة عميل، وسجل نشاط.

## د) نسخة العرض التجريبية + التقاط العملاء المحتملين

**موجود:** صفحة `/try/` ← نموذج ← يُحفظ Lead في جدول `leads` ← نظام تجريبي ببيانات `demo_seed`.

**ينقصه:**
- عيّنة demo أغنى (منتجات/عملاء/فواتير/مشاريع/مهام واقعية) ليرى المحتمل نظاماً ممتلئاً لا فارغاً.
- جولة تعريفية سريعة (tour) عند أول دخول.
- متابعة مبيعات للـ Leads (إشعار عند تسجيل مهتم جديد + حالة متابعة).

## هـ) نظام الشركة التقنية نفسه (Tenant الشركة)

- **أبقِ:** CRM، عروض الأسعار، الفوترة، الاشتراكات (فوترة دورية للأنظمة المُباعة)، المشاريع/التسليم، المهام، المصروفات، الفريق، لوحات البيانات.
- **أضِف:** تطبيق «العملاء/الأنظمة المُباعة» (إدارة الـ Tenants من داخل النظام)، العقود، تذاكر الدعم (Helpdesk)، قاعدة معرفة.
- **راجِع/أزِل:** ما لا يلزم شركة برمجيات (مثلاً «المواعيد» إن لم تُستخدم) لإبقاء الواجهة نظيفة.

## و) تطبيقات المحتوى (خاصة بعميل «إبراهيم سعود»)

| التطبيق | الحالة | الناقص |
|---------|--------|--------|

| مكتبة البرومتات | عرض أساسي | نسخ سريع، تصنيف/بحث |
| الهوية البصرية | غير موجود | واجهة كاملة |

## ز) أفضل الممارسات (نموذج Odoo) — التزامات دائمة

- تطبيقات مستقلة تُفعّل لكل شركة (الكتالوج + `tenant_apps`)، والاتجاه: تفكيك كل تطبيق كوحدة.
- مجموعات صلاحيات (groups) لكل تطبيق.
- بيانات تجريبية عند التثبيت.
- Chatter / Activities (سجل + متابعات) على كل سجل.
- تقارير وطباعة موحّدة وواجهة متّسقة.
- مبادئ صحّية: لا أسرار في الكود العام (المفتاح العام فقط)؛ وثّق كل تغيير قاعدة بيانات كملف SQL في `supabase/`؛ رقّم إصدار كل تطبيق.

## ح) خطة التنفيذ بالأولوية

### المرحلة أ — أساس البيع (الأهم)
1. الصلاحيات والأدوار + إدارة المستخدمين داخل العميل (واجهة كاملة فوق الجداول الموجودة).
2. نسخة demo غنية + تدفّق التقاط العملاء مكتمل (إشعار عند Lead جديد).
3. ✅ الموقع التعريفي الكامل على sa3ypodcast.com (الرئيسية + الخصوصية + الشروط) — **أُنجز في 2 يوليو 2026**.
4. نسخ احتياطي تلقائي لـ `app_state` (حماية قبل أي عميل).

### المرحلة ب — الإنتاجية
الاستيراد/التصدير (CSV/Excel) + التقارير والطباعة الموحّدة + سجل النشاط (Audit) + الإشعارات + البحث الشامل + مرفقات لكل سجل.

### المرحلة ج — الجاهزية التجارية السعودية
الفاتورة الإلكترونية ZATCA + المخزون + الفواتير الدورية + بوابة دفع + Helpdesk.

### المرحلة د — منصّة كاملة
تفكيك التطبيقات لوحدات + White-label (هوية لكل عميل) + لوحة تحكم متقدمة (مستخدمون/خطط/إصدارات/إحصاءات + دخول كعميل).

### التزامات مستمرة (كل مرحلة)
أمان (اختبار عزل الـ tenants ودوال التوكن) · أداء (pagination) · اختبارات آلية على مسارات البيع · تجاوب الجوال.

> **تذكير:** أي تطوير على الكود الأساسي ينطبق تلقائياً على كل العملاء — طوّر مرّة، يستفيد الجميع.
